## Context

原型评审发现：列表视图丢失**世界层关系**——账本中情报条目之间只有三类系统化连接（命中同一情报需求、被同一命题引用、信源关联），「W 公司」「电驱」这类对象只存在于陈述的自由文本里，系统看不出两条情报说的是同一家公司。

系统实际已在维护一张**系统对象**关联图（问题树、命题合成 DAG、证据引用、事件级合并与转引链、信源独立性），级联重估即沿其传播；缺的是**世界实体**层。跨课题复用（换品类带走知识底座）、实体级冷启动滚雪球、断连探测均以此为前提。

评审同时确认：该方向与既有架构原则干净兼容，不推翻任何已决事项（decision-01 提案制可容纳实体提案；实体锚定直接强化核实智能体的佐证检索与独立信源计数）。

## Decision

**实体（世界对象：机构 / 人物 / 产品 / 技术 / 地域等，类型集合随实现演进）纳入目标态领域模型**，作为两层知识（情报条目、命题）之下的知识底座。设计要点：

- **抽取为提案**：实体提及由智能体自陈述中抽取、挂载于情报条目与命题，经校验落账（decision-01 提案制、无溯源不落账——提案溯源到来源条目）；
- **归一走确认制**：实体同一性判定（归一）为判断层职责，合并参照双通道确认制先例（decision-09）——智能体提案、消费方确认；
- **实体不进判定链**：实体只锚定条目 / 命题，命题证据仍为情报条目 / 子命题，实体合并不触发级联重估；
- **连通度是测量变量**：供审查智能体相关性判断参考，不作有效性规则（断连三分——无关 / 新苗 / 链接失败——不可自动区分）；断连孤岛作新话题探测器（提示声明新情报需求）；
- **图谱视图为探究动线的呈现形态**：消费动线（推送卡片 / 列表）不变；

实现排期归 backlog，设计文档只写目标态。涉及文档：doc-01（两层知识加实体底座定位）、doc-02（实体与关系 + 归一操作）、doc-03（术语入表：实体、实体提及、实体归一）、doc-04（属性）、doc-06（抽取 / 归一职责归属）、doc-07（图谱视图）。

## Consequences

**会看到**：条目 / 命题挂实体锚点；图谱视图（生长的世界知识底座）成立；实体级滚雪球强化冷启动与核实质量；跨课题复用成立——实体邻域子图随新课题带走，复用知识带 as-of 时效（历史情报不作新鲜知识）；「不沉淀」痛点从结论层（命题留底）扩到知识层。

**付代价**：每条线索新增实体抽取判断的 LLM 成本（成本纪律受压）；实体归一错误会污染复用资产，合并 / 拆分操作需留痕与补偿语义；实体类型集合（本体）需长期演化维护；一轮六份文档联动修订。
