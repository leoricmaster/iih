## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
作为消费方与运维方，我想要对已登记的单个种子信源跑通完整的情报生产与反馈闭环，以便产出可溯源、带二维评级的情报条目供消费方浏览，并通过反馈持续校正信源信用。

范围（价值流）：种子信源登记（信源=发布主体，途径=采集入口，见术语表 §六）→ 两条素材入口并行产出线索——人工录入素材（线下途径，信源由采集智能体归因补记）与互联网信源自动拉取（已登记互联网途径）→ 审查智能体过滤（通过为候选、否决为噪音）→ 核实智能体评级（二维评级，落「已核实」）→ 收件箱浏览 → 一键类型化反馈 → 信用归因与信源信用更新。每步经状态机执行器提案落账，无溯源不落账。

范围外（后续里程碑加厚）：调度节奏、池外自由探索、多途径编排、主动推送、分发匹配、事件同一性、实体归一、级联重估传播深度。

非功能需求：落账全程审计可追溯（推理记录含公式版本、信用计算可重放）；单机部署可用；生产链各环节不做时延承诺（人工节奏）。
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Given 已登记信源 W 公司 · 官网（互联网途径）且情报需求已激活 When 系统自动拉取、经审查通过、核实评级 Then 消费方收件箱可见该条带二维评级的已核实情报条目，溯源五要素齐备（对照原型信源库页→条目详情→收件箱走查）
- [x] #2 Given 运维方录入素材（媒介会议讨论）When 经采集智能体归因补记信源与途径、审查通过、核实评级 Then 消费方收件箱可见该条带二维评级的已核实情报条目，溯源五要素齐备（对照原型录入素材页→条目详情→收件箱走查）
- [x] #3 Given 消费方对一条已核实条目给「有效」反馈 When 反馈路由与信用归因执行 Then 定位责任信源（转引链最早引入者），信用计算器按信源信用公式（数据设计 §2.3）更新分档，如实转述者不受奖惩
- [x] #4 Given 消费方给「事实错误」反馈并填理由 When 归因与计算执行 Then 条目打作废标记、责任信源信用扣减落账（级联重估本里程碑验证作废落账即可）
