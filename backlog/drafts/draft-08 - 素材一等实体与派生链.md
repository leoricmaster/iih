## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
素材升一等实体，统一两条采集路径的原文存储与「纪要视图」缺口（doc-02 现无素材实体；术语表「素材」仅见于载体定义句）。

建模（用户对等直觉 + 派生链）：
- **素材 = 最源头形态**，两路径对等：自动路径素材 = 抓回的网页（现 MinIO 内容寻址快照即它，未成实体）；人工路径素材 = 录音/照片/文档/当场文本。原文一份入对象存储，**不可变**（修订=追加派生，不编辑原文），带媒介/载体/采集时间/归因。
- **派生链 = 逐级加工形态**：转录稿、纪要稿、归一化文本等；每级记生产者（工具 ASR/OCR｜智能体 LLM｜人工）、输入源（素材或上一级）、产物引用；每级不可变、只追加。
- **条目挂链不挂快照**：情报条目引用素材 + 抽取所自的派生级（替代现逐条冗余 original_snapshot——实测一次访谈 24 条 × 全文 ≈ 250KB 冗余）。
- **纪要视图 = 素材详情页**：原文 + 派生链 + 关联条目及各自流水线进度，天然聚合，不另设「会议纪要」功能。

开放问题：派生分叉口径（同一转录稿出两版纪要——建议每级记 parent、允许轻分叉、不做树形 UI）；载体集合扩展与附件管线（IIH-01.09–11）衔接。

来源：MVP 验收讨论（IIH-01.13，2026-09-15），m-0 不动。
