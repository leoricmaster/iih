## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
现象：待确认信源「三一」（模型从纪要/转写稿归因抽取）经确认改名并入「三一集团」后，下次模型读到同类素材仍会抽出「三一」，归因按名精确匹配查无此行 → 又建一条待确认「三一」。确认/合并的知识不回流。

根因：归因是无状态 LLM 抽取（提示词不注入已知信源），落账按 name 精确匹配（_resolve_source），合并直接删待确认行、旧名不留。

候选方案（待梳理）：
- a) 记账层别名（推荐方向）：合并/改名时把旧名记为信源别名（Source 别名表或数组字段）；_resolve_source 按名或别名命中——别名命中已确认信源直接归因，不再重建待确认行。确定性、无 LLM 参与。
- b) 判断层辅助：归因提示词注入已确认信源名单（名+别名），帮助模型对齐「三一重工股份有限公司」→「三一集团」等模糊变体；名单增长需控制。
- c) 素材旁注/替换（不建议）：原文快照是溯源证据，改写破坏证据完整性；旁注只作用于单条素材，不可跨素材泛化。

来源：IIH-05.01 走查时用户提问。关联 IIH-04 反馈驱动的系统学习与校正、DRAFT-12 归因主体治理、doc-04 §1 实体别名集（实体已有别名，信源侧未建）。
