# IIH 术语表（Glossary）

> 本表是全项目**领域术语**的单一事实来源。代码命名、文档、Issue、日常沟通一律以本表为准。
> 分层按消费方**由外到内接触顺序**组织：要什么 → 怎么做 → 得到什么 → 从哪来 → 变聪明。
> 配套文档：[领域模型](doc-02%20-%20领域模型-Domain-Model.md)；架构与系统术语（三层、提案、记账层六模块）见[技术架构](doc-05%20-%20技术架构-Technical-Architecture.md)

## 维护规则

1. **禁止同义词混用**：不得用别名指代表内已有概念。
2. **修改术语是一次显式变更**：更新本表 → 同步《领域模型》→ 排查受影响代码与文档。
3. **状态术语只登记名**：状态一览表管 术语 + English + 一句话；迁移与边界规则以《领域模型》§4 为准，不在本表重复。改状态：先改《领域模型》，再同步对应一览行。

## 一、需求与研究课题（入口 · 要什么）

**对象与机制**

| 术语 | English | 定义 | 示例 |
|---|---|---|---|
| 消费方 | Consumer | 情报的需求者与使用者（人或系统） | 用户本人；经 API 引用结论的下游系统（间接消费） |
| 情报需求 | Intelligence Requirement (IR) | 消费方声明的兴趣配置，命中即推送条目 | 「长期跟踪 W 公司动态」 |
| 研究课题 | Research Question | 待回答的**问题**本身：登记后由系统跟踪求解，可递归分解为子课题（问题树），答案落成命题（decision-15） | 「自动装车市场空间有多大？」——分解为多个测算法子课题 |
| 提示词 | Prompt | 研究课题的伴随输入（自由文本，可空）：指标清单、测算框架、信源指引等，作为定向智能体分解与采集、分析智能体合成的上下文；留空则智能体自行发挥（decision-15） | 「单元存量法 / 工作量产能法两种测算法，矿卡保有量取大型露天矿」 |

> **如何选择**
> - 要**情报流**（命中即推送条目）→ 登记情报需求
> - 要**答案**（落成命题，可引用、可翻案）→ 登记研究课题

> **如何联动**
> - 需求两种来历：消费方**声明**，或被**催生**——研究课题催生的盯**输入**（结题即关），命题催生的盯**证据**（decision-15）
> - 研究课题只管**课题**生命周期（进行中 → 已结题）；判定 / 置信度 / 推理记录归**命题**，结题后命题仍存续、可翻案
> - **消费方**是委托方：收分发、给反馈、声明需求；流水线智能体读情报是生产环节，不是消费

**情报需求状态一览**——English 即代码命名；迁移见《领域模型》§4.1

| 状态 | English | 一句话 |
|---|---|---|
| 草稿 | Draft | 声明后待确认 |
| 激活 | Active | 驱动采集 |
| 暂停 | Paused | 挂起，不驱动采集 |
| 关闭 | Closed | 需求满足或撤销 |

**研究课题状态一览**——English 即代码命名；迁移见《领域模型》§4.2

| 状态 | English | 一句话 |
|---|---|---|
| 进行中 | In Progress | 登记问题后的默认态 |
| 已结题 | Concluded | 问题已回答或放弃；关催生的子需求，留历史 |

## 二、智能体与生产（系统内 · 怎么做）

| 术语 | English | 定义 | 示例 |
|---|---|---|---|
| 定向智能体 | Director | 将情报需求任务化、分派给采集智能体并管理采集节奏；将研究课题递归分解为子课题与情报需求 | 把「盯 W 公司公告」译为采集任务：途径 W 公司官网 · 节奏每日 |
| 采集任务 | Collection Task | 定向智能体任务化情报需求的产物：目标途径、检索参数、采集节奏 | 「每日抓取 W 公司官网动态页，关键词：合资」 |
| 采集智能体 | Collector | 按载体配备，执行采集任务（人工提交并入同一管线）产出**线索** | 网页类：抓取并解析页面，产出线索「W 与 Z 拟合资」 |
| 审查智能体 | Reviewer | 对线索做质量把关：相关性、语义去重（事件同一性判定）、有效性初筛 | 判该线索与需求相关、非同源重复 → 放行为候选 |
| 核实智能体 | Verifier | 交叉验证：事件同一性判定（合并印证）→ 穿透转引链 → 统计独立信源 → 评定内容可信度（1–6） | 穿透转载链至 W 公司官网原文，独立信源计 1，评 B2 |
| 分析智能体 | Analyst | 对研究课题的答案命题做判定产出结论：叶子课题从已核实情报、非叶子课题从子课题结论按框架合成 | 取子命题 C2a「1,351–3,336 台」、C2b 按交集框架合成 C2 |

> **如何分工**
> - 定向是需求与采集之间的**翻译层**
> - 抓取 / 解析 / ASR / OCR 等无状态功能是采集智能体的**工具**，非其本体
> - 审查管"该不该收"；核实管"是不是真的"
> - 分析是答案生命周期的引擎

## 三、情报（第一层产品 · 世界说了什么）

**对象与机制**

| 术语 | English | 定义 | 示例 |
|---|---|---|---|
| 情报条目 | Intelligence Item | 系统的原子产品：**偏客观的陈述** + 完整溯源 + 二维评级 + 状态。口语简称"情报" | I1：陈述「W 与 Z 成立合资公司」+ 转引链 + 评级 B2 + 状态 |
| 情报评级 | Rating | 二维评价：信源可靠度（A–F）× 内容可信度（1–6），书写形如 **B2** | B2 = 信源通常可靠 × 很可能为真 |
| 评级重评 | Rating Reassessment | 对已核实条目重新评定，评级历史版本化保留、可重放 | 新印证并入后 B2 → B1，历史版本留档 |
| 内容可信度 | Credibility | 评级的第二维：1 已被独立信源证实 … 6 无法判断 | 独立信源 N = 2 → 可信度 1 |
| 事件时间 | Event Time | 情报所述事实的发生时间 | 公告发布日 08-30（采集日 09-02，时效按前者算） |
| 出处信源 | Provenance Source | 事件级合并后情报条目对外标示的唯一信源 = 转引链上最早引入该陈述的信源 | I1 的出处信源 = W 官网（最早陈述方），非转载站 |
| 分发记录 | Dissemination Record | 条目 × 消费方的送达与反馈记账：命中需求、渠道、送达 / 反馈时间 | I1 × 消费方 × IM 渠道，09-01 送达、当日反馈 |
| 作废 | Retracted | 有效性**标记位**而非状态：打在已核实条目上，保留原状态 | I1 证实为误报 → 打标记、保留已核实态、停发并级联重估 |

> **易混点**
> - 「客观陈述」是内容属性；条目是含全部元数据的完整实体
> - 评级两维**正交**（详见《领域模型》§5）
> - 评级重评针对**条目**；级联重估针对**结论**
> - 对外引用取**条目**；条目内标**出处信源**消歧（= 信用归因对象，decision-08）
> - 分发按**分发记录**记账：条目状态不承载分发进度
> - 作废是**标记位**而非状态

**情报条目状态一览**——English 即代码命名；迁移与边界见《领域模型》§4.3

| 状态 | English | 一句话 |
|---|---|---|
| 线索 | Lead | 采集产出，未经审查 |
| 候选 | Candidate | 审查通过，待核实 |
| 已核实 | Verified | 核实通过并完成评级 |
| 存疑 | Undetermined | 核实无法完成，挂起待复核 |
| 噪音 | Noise | 审查否决的终态 |
| 否决 | Rejected | 核实否决的终态 |

## 四、命题（第二层产品 · 信什么）

**对象与机制**

| 术语 | English | 定义 | 示例 |
|---|---|---|---|
| 命题 | Claim | 可判真假的陈述——求证/核实线的原子单位，有独立状态与生命周期（decision-15） | C1「W 与 Z 将成立合资公司」；C2「装车市场空间 1,600–3,300 台」 |
| 置信度 | Confidence | 高 / 中 / 低（参考 ICD 203 风格） | C2 合成判定后：中 |
| 推理记录 | Reasoning Record | 命题每次判定落档的依据快照：引用的情报条目 / 命题（子结论作合成证据）+ 判定规则 + 判定者（人或智能体）+ 时间 | C1 证实：引用 I1 · 公式 v1 · 分析智能体 · 09-01 |
| 级联重估 | Cascade Reassessment | 情报作废 → 引用它的命题重估 → 引用该命题的下游命题重新评估（沿合成 DAG） | 「矿卡保有量」条目作废 → C2a 重估 → C2 重估 |

> **从哪来**
> - **世界递来的断言**（独立登记）；**研究课题的答案**（答案命题 / 子结论）

> **如何判定**
> - 判定二分：**求证核实**（叶子 · 证据 = 情报条目）/ **逻辑合成**（非叶子 · 证据 = 子命题），各自置信度公式（decision-15）
> - 判出的是**结论**：当前生效的评估 + 置信度——情报领域只有置信度，没有数学证明
> - **已证伪**留底（负知识），不删不弃，避免重复提出、辅助排除
> - 判定 / 置信度 / 推理记录 / 反馈均以**命题**为单位——同一命题可被多个问题引用

**命题状态一览**——English 即代码命名；迁移与边界见《领域模型》§4.4

| 状态 | English | 一句话 |
|---|---|---|
| 假设 | Hypothesis | 待验证；证实后改称结论 |
| 结论 | Assessment | 当前生效判定，带置信度，可直接引用 |
| 重估中 | Reassessing | 结论被新证据或级联触发，在估 |
| 已证伪 | Refuted Claim | 证伪留底（负知识） |
| 存疑 | Undetermined | 证据不足，无法判定 |

## 五、实体（知识底座 · 说的是谁）

| 术语 | English | 定义 | 示例 |
|---|---|---|---|
| 实体 | Entity | 世界对象（机构 / 人物 / 产品 / 技术 / 地域等，类型集合随实现演进），有身份、可归一、可被提及；知识底座，跨课题沉淀与复用 | W 公司、矿卡、电驱、北方露天矿 |
| 实体提及 | Entity Mention | 陈述中出现的实体引用，挂载于情报条目与命题，溯源到来源条目 | I1「W 公司矿卡交付量」挂提及：W 公司、矿卡 |
| 实体归一 | Entity Resolution | 判定两个提及 / 实体指向同一对象的判断（判断层职责）：新实体随提及建立，归并既有实体走提案 + 消费方确认 | 「W 集团」「W 公司」判定同一实体并归并，留痕 |

> **易混点**
> - 实体 ≠ 信源：信源是情报的**责任**对象（谁说的），实体是被陈述的**世界**对象（说的是谁）——两层经实体 ID 挂接互查，但不合并、各管各的账：W 公司（信源）管信用与立场，W 公司（实体）管被谁提及
> - 实体间关系边**不落账**：由条目 / 命题的提及共现派生（投影），图谱视图与检索用
> - 实体**不进判定链**：命题证据仍为情报条目 / 子命题，归并不触发级联重估
> - 实体无状态机：归并 / 拆分为留痕操作，非状态迁移
> - 图连通度是**测量变量**（审查相关性参考），不作有效性规则；断连孤岛作新话题探测器（提示声明新情报需求）

## 六、信源（证据出身 · 从哪来）

| 术语 | English | 定义 | 示例 |
|---|---|---|---|
| 媒介 | Medium | 情报的**获取场景**，封闭小集合：互联网 / 用户访谈 / 行业展会 / 行业交流 / 内部会议 / 文档阅读 | 互联网、用户访谈、行业展会 |
| 载体 | Modality | 原始素材的**物理形态**：网页 / 录音 / 文字 / 图片 / 文档 | 网页、录音、图片 |
| 信源 | Source | 情报的**发布主体**（谁在说：公司 / 政府 / 组织 / 媒体 / 人物 / 其他，类型随实现演进），挂立场偏差、独立性关联与信用，可挂实体 | W 公司、新华社、某行业媒体、张三 |
| 途径 | Outlet | 主体的**发布出口**（从哪说），归属唯一信源：采集入口（网址 / RSS / 账号 / 线下场景）+ 媒介 + 载体能力 + 更新节奏 + 领域侧重；采集任务对途径派发 | W 公司的官网与公众号（同主体两途径）、华矿装备观察的公众号 |
| 信源画像 | Source Profile | 信源与其途径的完整档案：主体挂立场偏差、独立性关联、历史信用，途径挂更新节奏、领域侧重 | 某行业媒体（主体）立场偏乐观、信用 B；其公众号（途径）日更、领域矿山装备 |
| 信源库 | Source Registry | 已准入信源及其途径的全集 | 已准入信源列表；待确认的发现不入库 |
| 信源信用 | Source Credit | 信源可靠度的动态评价，取 Admiralty A–F（见「评级体系」），记在主体上不按途径拆分 | W 公司：A |
| 一次信源 | Primary Source | 信息的原始产出方（如：新华社发的通稿） | 新华社发的通稿 |
| 二次信源 | Secondary Source | 转述方（如：转载通稿的行业网站） | 转载通稿的行业网站 |
| 转引链 | Provenance Chain | 一条情报的完整溯源路径：载体 → … → 原始信源；节点记信源 × 途径 × 载体 × 时间 | 行业网站（网页）→ 新华社（通稿）→ 发布会现场（录音） |
| 独立信源 | Independent Source | 转引链互不交汇的信源，**按发布主体计数** | 5 家媒体转载同一通稿 = 1 个独立信源；同主体官网 + 公众号 = 1 |

> **易混点**
> - 信源 ≠ 途径：信源是**主体**（谁在说），途径是**出口**（从哪说）；采集任务对途径派发，信用与独立性归主体
> - 途径 ≠ 媒介 ≠ 载体：途径是具体出口（W 公司官网），媒介是获取场景（互联网），载体是素材形态（网页）
> - 「渠道」留给分发记录（delivery channel），不作信源侧术语
> - 画像 ≠ 信用：信用只是画像中的动态字段
> - 新信源经双通道确认制准入（decision-09）；未确认不入库、不建画像、不记账
> - 核实计数须穿透转引链至**一次信源**

## 七、反馈（闭环 · 变聪明）

| 术语 | English | 定义 | 示例 |
|---|---|---|---|
| 反馈 | Feedback | 消费方对情报 / 结论的类型化评价 | 对 I1 一键「有效」；对结论 C1 提「事实错误」 |
| 有效 / 事实错误 / 重复/噪音 / 不相关 / 过期 / 评级异议 | Valid / Factual Error / Duplicate-Noise / Irrelevant / Outdated / Rating Dispute | 反馈的六类型 | 推送卡片一键「过期」；详情页补写理由的「评级异议」 |
| 信用归因 | Credit Attribution | 将有效 / 事实错误反馈定位到责任信源：转引链上最早引入该陈述的信源，如实转述者不受奖惩 | 「有效」归因到 W 官网（最早陈述方），如实转载的资讯站不动 |

> **反馈规则**
> - 类型必填；理由默认「快捷 · {类型}」，Web 可补写，**事实错误必填**
> - 各类型路由见《领域模型》§6；仅**有效 / 事实错误**动信用
> - 归因是判断层的**提案**；奖惩由记账层执行
