# IIH 术语表（Glossary）

> 本表是全项目术语的**单一事实来源**。代码命名、文档、Issue、日常沟通一律以本表为准。
> 配套文档：[领域模型](doc-02%20-%20领域模型-Domain-Model.md)

## 维护规则

1. **禁止同义词混用**：不得用别名指代表内已有概念。
2. **修改术语是一次显式变更**：更新本表 → 同步《领域模型》→ 排查受影响代码与文档。

---

## 一、来源层

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 媒介 | Medium | 情报的**获取场景**，封闭小集合：互联网 / 用户访谈 / 行业展会 / 行业交流 / 内部会议 / 文档交换 | 描述"在什么场合拿到"；溯源元数据、画像输入，**不承载信用**；采集模式（自动拉取 / 人工提交）由媒介派生 |
| 载体 | Modality | 原始素材的**物理形态**：网页 / 录音 / 文字 / 图片 / 文档 | 决定采集智能体的处理管线（ASR / OCR / 解析）；与媒介正交，一次采集 = 场景 × 形态 |
| 信源 | Source | 情报的**责任实体**（机构 / 站点 / 人物），有身份、可画像、可记账 | 描述"谁说的"；**信用只能记在信源上**。一个信源可跨越多个媒介 |
| 信源画像 | Source Profile | 信源的完整档案：领域覆盖、更新频率、立场偏差、历史信用、独立性关联 | 画像 ≠ 信用：信用只是画像中的一个动态字段 |
| 信源库 | Source Registry | 已准入信源的全集 | 新信源经双通道确认制准入（decision-09）；未确认的发现不入库、不建画像、不记账 |
| 信源信用 | Source Credit | 信源可靠度的动态评价，取 Admiralty A–F（见「评级体系」） | 由历史反馈驱动更新，更新过程必须可重放（架构原则） |
| 一次信源 | Primary Source | 信息的原始产出方（如：新华社发的通稿） | 与「二次信源」相对 |
| 二次信源 | Secondary Source | 转述载体（如：转载通稿的行业网站） | 核实计数时须穿透到一次信源 |
| 转引链 | Provenance Chain | 一条情报的完整溯源路径：载体 → … → 原始信源 | 情报条目的必备字段；核实与独立性判断的依据 |
| 独立信源 | Independent Source | 转引链互不交汇的信源 | 交叉验证的计数单位：N 家转载同一通稿 = **1 个**独立信源 |

## 二、需求与生产层

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 情报需求 | Intelligence Requirement (IR) | 消费方声明的兴趣配置，分两类：**订阅**（长期）与**任务**（临时） | 一等实体，有自己的生命周期；驱动采集；可由命题催生（decision-12） |
| 方法学附件 | Methodology Attachment | 挂载于命题（或情报需求）的结构化文档：指标清单、测算框架、信源指引 | 输入供货而非判断主体：由记账层组装注入定向与分析上下文（decision-12）；自定义工具 / 智能体列 v2 |
| 消费方 | Consumer | 情报的需求者与使用者（人或系统） | 消费分两级：直接消费（读情报）、间接消费（引用结论） |
| 采集智能体 | Collector | 按载体配备，依据情报需求产出**线索** | 每种载体一类；抓取/解析/ASR/OCR 等无状态功能是其**工具**，非其本体 |
| 审查智能体 | Reviewer | 对线索做质量把关：相关性、语义去重（事件同一性判定）、有效性初筛 | 产出：候选情报 或 噪音 |
| 核实智能体 | Verifier | 交叉验证：事件同一性判定（合并印证）→ 穿透转引链 → 统计独立信源 → 评定内容可信度（1–6） | 与审查分工：审查管"该不该收"，核实管"是不是真的" |
| 分析智能体 | Analyst | 基于已核实情报对命题做证实 / 证伪 / 存疑判定，产出结论 | 假设生命周期的引擎 |
| 定向智能体 | Director | 将情报需求任务化、分派给采集智能体，并管理采集节奏 | 需求与采集之间的调度翻译层 |

## 三、情报层

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 情报条目 | Intelligence Item | 系统的原子产品：**偏客观的陈述** + 完整溯源 + 二维评级 + 状态。口语简称"情报" | "客观陈述"是内容属性；情报条目是含全部元数据的完整实体 |
| 线索 | Lead | 情报条目的初始状态：采集智能体产出、未经审查 | |
| 候选情报 | Candidate | 审查通过、待核实的中间状态 | |
| 已核实 | Verified | 核实通过、完成评级——"情报"之名的严格起点 | 线索与候选是半成品 |
| 已分发 | Disseminated | 已核实情报经匹配送达至少一个消费方 | 与已核实分离以便度量需求覆盖 |
| 已消费 | Consumed | 消费方接收并给出反馈 | 反馈的挂载点 |
| 噪音 | Noise | 审查否决的终态（不相关 / 重复 / 无效） | 「重复」限同源纯重复；跨信源同事件是印证，放行核实合并（decision-10） |
| 否决 | Rejected | 核实否决的终态（有证据判定陈述不实） | 无法印证或反证未达证伪强度 → 弱评级或存疑，不否决 |
| 作废 | Retracted | 已核实情报事后被推翻的状态，**触发级联重估** | 非普通终态：依赖它的结论必须重估 |
| 情报评级 | Rating | 二维评价：信源可靠度（A–F）× 内容可信度（1–6），书写形如 **B2** | 源自 NATO/Admiralty 体系，详见《领域模型》§5 |
| 评级重评 | Rating Reassessment | 对已核实条目重新评定，评级历史版本化保留、可重放 | 触发与机制见《领域模型》§5.1；区别于级联重估（针对命题） |
| 内容可信度 | Credibility | 评级的第二维：1 已被独立信源证实 … 6 无法判断 | 由核实智能体评定 |
| 事件时间 | Event Time | 情报所述事实的发生时间 | 与「采集时间」区分；时效计算基于事件时间 |
| 出处信源 | Provenance Source | 事件级合并后情报条目对外标示的唯一信源 = 转引链上最早引入该陈述的信源 | 与「信用归因」对象一致（decision-08）；对外引用取条目本身，条目内标出处信源以消歧 |

## 四、命题层

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 命题 | Claim | 假设与结论的**统一抽象**：一个可判真假的陈述 | 假设 / 结论是同一实体在不同状态 |
| 假设 | Hypothesis | 待验证状态的命题 | 证实后即改称结论 |
| 结论 | Assessment | 已验证、当前生效的命题，带置信度，**可直接引用** | 可翻案：被新证据挑战时进入重估 |
| 重估中 | Reassessing | 结论被新证据或级联重估触发的在估状态 | 出口：维持 / 修订、降级存疑、推翻为已证伪 |
| 已证伪命题 | Refuted Claim | 被证伪的命题，默认稳态 | 负知识资产（避免重复提出、辅助排除法）；证伪依据动摇（如所引情报作废）时进入重估 |
| 存疑 | Undetermined | 无法判定状态，可设复核期 | 成因两侧不同：情报侧 = 核实无法完成，命题侧 = 证据不足；弱评级（4–6）与挂存疑的边界见《领域模型》§4.1 |
| 置信度 | Confidence | 高 / 中 / 低（参考 ICD 203 风格） | 与"证实"的布尔语义区分：情报领域只有置信度，没有数学证明 |
| 推理记录 | Reasoning Record | 命题每次判定落档的依据快照：引用的情报条目 + 判定规则 + 判定者（人或智能体）+ 时间 | 结论可审计、可级联重估的前提 |
| 级联重估 | Cascade Reassessment | 情报作废 → 自动触发依赖它的结论重新评估 | 由推理记录支撑 |

## 五、反馈层

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 反馈 | Feedback | 消费方对情报 / 结论的类型化评价 | 类型必填；理由默认「快捷 · {类型}」模板、Web 可补写，事实错误必填（decision-11）；不同类型路由到不同更新点 |
| 有效 / 事实错误 / 重复/噪音 / 不相关 / 过期 / 评级异议 | Valid / Factual Error / Duplicate-Noise / Irrelevant / Outdated / Rating Dispute | 反馈的六类型 | 路由表见《领域模型》§6 |
| 信用归因 | Credit Attribution | 将有效 / 事实错误反馈定位到责任信源：转引链上最早引入该陈述的信源，如实转述者不受奖惩 | 归因判断属判断层（提案），奖惩由记账层执行 |

## 六、架构术语

| 术语 | English | 定义 |
|---|---|---|
| 判断层 | Judgment Layer | 由智能体承担的语义判断类工作（采集 / 审查 / 核实 / 分析 / 定向） |
| 记账层 | Ledger Layer | 确定性系统：状态机、信用计算、溯源存储、分发检索、调度、反馈路由 |
| 工具层 | Tool Layer | 无状态传统功能（fetcher / 解析器 / 检索 / 存储读写），作为智能体的工具 |
| 提案 | Proposal | 智能体对记账层的写入形式：产出 + 依据 + 溯源（按提案类型分级必填，结构见架构 §5），经校验后落账 |
| 状态机执行器 | State Machine Executor | 记账层唯一写账入口：接收提案 → 校验 → 执行状态迁移 → 落账 |
| 信用计算器 | Credit Calculator | 按 decision-04 公式计算信源信用分档；同一反馈历史重算得同一值（可重放） |
| 溯源存储 | Provenance Store | 情报条目、命题、推理记录、反馈的持久化；无溯源不落账 |
| 分发检索 | Dissemination Search | 订阅匹配与消费方推送；已核实才可分发 |
| 调度 | Scheduler | 智能体任务分派、采集节奏、存疑复核与评级重评触发（decision-03/07）；事件驱动优先，定时兜底 |
| 反馈路由 | Feedback Router | 类型化反馈分发到三通路；接收信用归因提案（decision-08），仅有效/事实错误动信用 |
