# IIH 术语表（Glossary）

> 本表是全项目**领域术语**的单一事实来源。代码命名、文档、Issue、日常沟通一律以本表为准。
> 配套文档：[领域模型](doc-02%20-%20领域模型-Domain-Model.md)；架构与系统术语（三层、提案、记账层六模块）见[技术架构](doc-05%20-%20技术架构-Technical-Architecture.md)

## 维护规则

1. **禁止同义词混用**：不得用别名指代表内已有概念。
2. **修改术语是一次显式变更**：更新本表 → 同步《领域模型》→ 排查受影响代码与文档。
3. **状态术语只登记名**：状态一览表管 术语 + English + 一句话；迁移与边界规则以《领域模型》§4 为准，不在本表重复。改状态：先改《领域模型》，再同步对应一览行。

## 一、来源层

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 媒介 | Medium | 情报的**获取场景**，封闭小集合：互联网 / 用户访谈 / 行业展会 / 行业交流 / 内部会议 / 文档交换 | 描述"在什么场合拿到"；溯源元数据、画像输入，**不承载信用**；采集模式（自动拉取 / 人工提交）由媒介派生 |
| 载体 | Modality | 原始素材的**物理形态**：网页 / 录音 / 文字 / 图片 / 文档 | 决定采集智能体的处理管线（ASR / OCR / 解析）；与媒介正交，一次采集 = 场景 × 形态 |
| 信源 | Source | 情报的**责任实体**（机构 / 站点 / 人物），有身份、可画像、可记账 | 描述"谁说的"；**信用只能记在信源上**。一个信源可跨越多个媒介 |
| 信源画像 | Source Profile | 信源的完整档案：领域覆盖、更新频率、立场偏差、历史信用、独立性关联 | 画像 ≠ 信用：信用只是画像中的一个动态字段 |
| 信源库 | Source Registry | 已准入信源的全集 | 新信源经双通道确认制准入（decision-09）；未确认的发现不入库、不建画像、不记账 |
| 信源信用 | Source Credit | 信源可靠度的动态评价，取 Admiralty A–F（见「评级体系」） | 由历史反馈驱动更新，更新过程必须可重放（架构原则） |
| 一次信源 | Primary Source | 信息的原始产出方（如：新华社发的通稿） | 与「二次信源」相对 |
| 二次信源 | Secondary Source | 转述载体（如：转载通稿的行业网站） | 核实计数时须穿透到一次信源 |
| 转引链 | Provenance Chain | 一条情报的完整溯源路径：载体 → … → 原始信源 | 情报条目的必备字段；核实与独立性判断的依据 |
| 独立信源 | Independent Source | 转引链互不交汇的信源 | 交叉验证的计数单位：N 家转载同一通稿 = **1 个**独立信源 |

## 二、需求与生产层

**对象与机制**

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 情报需求 | Intelligence Requirement (IR) | 消费方声明的兴趣配置，分两类：**订阅**（长期）与**专项**（临时） | 一等实体，有自己的生命周期；驱动采集；可由课题催生（盯参数）或命题催生（盯证据，decision-15）；判别——要**情报流**（命中即推送条目）是需求，要**答案**（落成命题）是课题 |
| 消费方 | Consumer | 情报的需求者与使用者（人或系统） | 消费分两级：直接消费（读情报）、间接消费（引用结论） |
| 采集任务 | Collection Task | 定向智能体任务化情报需求的产物：目标信源与媒介、检索参数、采集节奏 | 采集智能体的直接输入、调度重试的单位；领域内「任务」一词仅剩此义 |
| 采集智能体 | Collector | 按载体配备，执行采集任务（人工提交并入同一管线）产出**线索** | 每种载体一类；抓取/解析/ASR/OCR 等无状态功能是其**工具**，非其本体 |
| 审查智能体 | Reviewer | 对线索做质量把关：相关性、语义去重（事件同一性判定）、有效性初筛 | 产出：候选 或 噪音 |
| 核实智能体 | Verifier | 交叉验证：事件同一性判定（合并印证）→ 穿透转引链 → 统计独立信源 → 评定内容可信度（1–6） | 与审查分工：审查管"该不该收"，核实管"是不是真的" |
| 分析智能体 | Analyst | 对课题的答案命题做判定产出结论：叶子课题从已核实情报、非叶子课题从子课题结论按框架合成 | 答案生命周期的引擎 |
| 定向智能体 | Director | 将情报需求任务化、分派给采集智能体并管理采集节奏；按附件将课题递归分解为子课题与情报需求 | 需求与采集之间的调度翻译层 |

**状态一览（情报需求）**——English 即代码命名；迁移见《领域模型》§4.3

| 状态 | English | 一句话 |
|---|---|---|
| 草稿 | Draft | 声明后待确认 |
| 激活 | Active | 驱动采集 |
| 暂停 | Paused | 挂起，不驱动采集 |
| 关闭 | Closed | 需求满足或撤销 |

## 三、情报层

**对象与机制**

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 情报条目 | Intelligence Item | 系统的原子产品：**偏客观的陈述** + 完整溯源 + 二维评级 + 状态。口语简称"情报" | "客观陈述"是内容属性；情报条目是含全部元数据的完整实体 |
| 情报评级 | Rating | 二维评价：信源可靠度（A–F）× 内容可信度（1–6），书写形如 **B2** | 源自 NATO/Admiralty 体系，详见《领域模型》§5 |
| 评级重评 | Rating Reassessment | 对已核实条目重新评定，评级历史版本化保留、可重放 | 触发与机制见《领域模型》§5.1；区别于级联重估（针对结论） |
| 内容可信度 | Credibility | 评级的第二维：1 已被独立信源证实 … 6 无法判断 | 由核实智能体评定 |
| 事件时间 | Event Time | 情报所述事实的发生时间 | 与「采集时间」区分；时效计算基于事件时间 |
| 出处信源 | Provenance Source | 事件级合并后情报条目对外标示的唯一信源 = 转引链上最早引入该陈述的信源 | 与「信用归因」对象一致（decision-08）；对外引用取条目本身，条目内标出处信源以消歧 |
| 分发记录 | Dissemination Record | 条目 × 消费方的送达与反馈记账：命中需求、渠道、送达 / 反馈时间 | 需求覆盖度量的数据源；条目状态不承载分发进度 |
| 作废 | Retracted | 有效性**标记位**而非状态：打在已核实条目上，保留原状态 | 触发级联重估与翻案警报（decision-11）；打标记后不再分发 |

**状态一览（情报条目）**——English 即代码命名；迁移与边界见《领域模型》§4.1

| 状态 | English | 一句话 |
|---|---|---|
| 线索 | Lead | 采集产出，未经审查 |
| 候选 | Candidate | 审查通过，待核实 |
| 已核实 | Verified | 核实通过并完成评级 |
| 存疑 | Undetermined | 核实无法完成，挂起待复核 |
| 噪音 | Noise | 审查否决的终态 |
| 否决 | Rejected | 核实否决的终态 |

## 四、命题层

**对象与机制**

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 课题 | ResearchQuestion | 待回答**问题**的一等容器，可递归分解为子课题（问题树）：问题陈述 + 附件（自由文本，可空）+ 催生的专项情报需求或子课题 + 工作台聚合（decision-15） | 问题线（生产-合成）的容器：只管问题生命周期（进行中→已结题）；答案落成命题（登记即判定），判定/置信度/推理记录归命题；结题即关子需求、保留历史；附件（方法学、信源指引等）注入定向与分析上下文，留空则智能体自行发挥 |
| 命题 | Claim | 可判真假的陈述，**一等对象**——求证/核实线的原子单位（decision-15） | 可独立登记（世界递来的断言）、可归属课题（答案命题 / 子结论）、可被多个问题引用；假设/结论/已证伪是其状态；判定、置信度、推理记录、反馈以命题为单位；**判定方式二分：求证核实（叶子·证据=情报条目）/ 逻辑合成（非叶子·证据=子命题）**，各自置信度公式（decision-15）；可催生情报需求（盯证据）；已证伪默认稳态留底（负知识） |
| 置信度 | Confidence | 高 / 中 / 低（参考 ICD 203 风格） | 与"证实"的布尔语义区分：情报领域只有置信度，没有数学证明 |
| 推理记录 | Reasoning Record | 命题每次判定落档的依据快照：引用的情报条目 / 命题（子结论作合成证据）+ 判定规则 + 判定者（人或智能体）+ 时间 | 结论可审计、可级联重估的前提 |
| 级联重估 | Cascade Reassessment | 情报作废 → 引用它的命题重估 → 引用该命题的下游命题重新评估（沿合成 DAG） | 由推理记录支撑 |

**状态一览（命题）**——English 即代码命名；迁移与边界见《领域模型》§4.2

| 状态 | English | 一句话 |
|---|---|---|
| 假设 | Hypothesis | 待验证；证实后改称结论 |
| 结论 | Assessment | 当前生效判定，带置信度，可直接引用 |
| 重估中 | Reassessing | 结论被新证据或级联触发，在估 |
| 已证伪 | Refuted Claim | 证伪留底（负知识） |
| 存疑 | Undetermined | 证据不足，无法判定 |

**状态一览（课题）**——English 即代码命名；迁移见《领域模型》§4.4

| 状态 | English | 一句话 |
|---|---|---|
| 进行中 | In Progress | 登记问题后的默认态 |
| 已结题 | Concluded | 问题已回答或放弃；关催生的子需求，留历史 |

## 五、反馈层

| 术语 | English | 定义 | 关键区分 |
|---|---|---|---|
| 反馈 | Feedback | 消费方对情报 / 结论的类型化评价 | 类型必填；理由默认「快捷 · {类型}」模板、Web 可补写，事实错误必填（decision-11）；不同类型路由到不同更新点 |
| 有效 / 事实错误 / 重复/噪音 / 不相关 / 过期 / 评级异议 | Valid / Factual Error / Duplicate-Noise / Irrelevant / Outdated / Rating Dispute | 反馈的六类型 | 路由表见《领域模型》§6 |
| 信用归因 | Credit Attribution | 将有效 / 事实错误反馈定位到责任信源：转引链上最早引入该陈述的信源，如实转述者不受奖惩 | 归因判断属判断层（提案），奖惩由记账层执行 |
