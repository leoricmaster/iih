# IIH 领域模型

> 术语以[术语表](doc-03%20-%20术语表-Glossary.md)为准，本文不重复定义。

## 1. 总览

一句话：**媒介是"在哪儿拿到的"，载体是"什么形态"，信源是"谁说的"，情报是"说了什么"，命题是"我们信什么"。**

系统 = 经典情报循环（定向 → 采集 → 处理 → 分析 → 分发 → 反馈）的智能体化 + 类型化反馈闭环，全景见 §6。

## 2. 实体与属性

| 实体 | 核心属性 | 说明 |
|---|---|---|
| 媒介 | 名称、描述 | 获取场景的封闭小集合；采集模式（自动拉取 / 人工提交）由媒介派生 |
| 载体 | 名称、处理管线（ASR / OCR / 解析） | 素材形态的封闭小集合；采集智能体按载体分类 |
| 信源 | 标识、类型（机构/站点/人物）、画像、信用（A–F）、独立性关联 | 信用是画像的动态字段 |
| 情报需求 | 提出方、类型（订阅/任务）、内容规格、生效窗口、状态 | 内容规格 = 主题、关键词、信源偏好、时效要求等 |
| 情报条目 | 陈述内容、溯源（信源引用+载体+媒介+采集时间+原文快照/链接）、事件时间、评级、状态、命中需求 | 溯源含完整转引链；原文留存不可变；陈述以原文为准、附机翻（decision-05） |
| 命题 | 陈述、当前状态、置信度、推理记录列表、关联需求（可空） | 假设/结论/已证伪/存疑是同一实体的状态 |
| 推理记录 | 引用的情报条目、判定规则（含公式版本）、判定者（人或智能体）、时间 | 命题每次判定落档；级联重估的依据 |
| 反馈 | 类型、理由、目标（情报条目或命题）、评价方、时间 | 类型枚举见 §7 |

## 4. 状态机

### 4.1 情报条目

```mermaid
stateDiagram-v2
    [*] --> 线索: 采集智能体产出
    线索 --> 候选情报: 审查通过
    线索 --> 噪音: 审查否决（不相关/重复/无效）
    候选情报 --> 已核实: 核实通过（评级 A1–F6）
    候选情报 --> 否决: 核实否决
    候选情报 --> 存疑: 核实无法完成（挂起，可设复核期）
    存疑 --> 候选情报: 复核期到 / 新证据
    已核实 --> 已分发: 分发
    已分发 --> 已消费: 消费方接收并反馈
    已核实 --> 作废: 事后推翻（触发级联重估）
    已分发 --> 作废: 事后推翻（触发级联重估）
    已消费 --> 作废: 事后推翻（触发级联重估）
    噪音 --> [*]
    否决 --> [*]
    作废 --> [*]
```

要点：能完成评定的给弱评级（4–6）仍为已核实；核实无法完成才挂存疑。

### 4.2 命题

```mermaid
stateDiagram-v2
    [*] --> 假设: 提出
    假设 --> 结论: 证实（附置信度与推理记录）
    假设 --> 已证伪: 证伪
    假设 --> 存疑: 无法判定（可设复核期）
    存疑 --> 假设: 复核期到 / 新证据
    结论 --> 重估中: 新证据挑战
    重估中 --> 结论: 维持 / 修订（置信度更新）
    重估中 --> 存疑: 证据不再支持（降级）
    重估中 --> 已证伪: 推翻
    存疑 --> 结论: 复核证实（置信度与推理记录）
    已证伪 --> 重估中: 证伪依据动摇
```

要点：**结论不是终点态，是"当前生效"态**；已证伪默认稳态但可重估（证伪本身依据情报条目）。每次状态迁移都落一条推理记录。

### 4.3 情报需求

```mermaid
stateDiagram-v2
    [*] --> 草稿
    草稿 --> 激活: 确认
    激活 --> 暂停: 挂起
    暂停 --> 激活: 恢复
    激活 --> 关闭: 需求满足或撤销
    暂停 --> 关闭
    关闭 --> [*]
```

## 5. 评级体系（Admiralty / NATO 二维制）

| 维度 | 评级 | 维护者 |
|---|---|---|
| 信源可靠度 | A 完全可靠 ｜ B 通常可靠 ｜ C 相当可靠 ｜ D 通常不可靠 ｜ E 不可靠 ｜ F 无法判断 | 信源画像（反馈驱动） |
| 内容可信度 | 1 已被独立信源证实 ｜ 2 很可能为真 ｜ 3 可能为真 ｜ 4 可疑 ｜ 5 不太可能 ｜ 6 无法判断 | 核实智能体（独立信源交叉） |

两维正交，书写形如 **B2**（选型依据见 decision-08）。

### 5.1 评级重评（decision-09）

已核实条目可重新评定，经提案落账；评级历史版本化保留（可重放），下游引用取当前值。触发器：新印证合并（decision-02）｜信源信用分档迁移（decision-04）｜人工触发｜评级异议（§7）。

## 7. 反馈类型与路由

| 反馈类型 | 更新信源信用 | 更新需求/采集配置 | 迭代智能体 | 其他动作 |
|---|---|---|---|---|
| 有效 | ↑（仅责任信源） | 正向微调 | — | — |
| 事实错误 | ↓↓（仅责任信源） | — | 核实收紧（独立信源计数要求提高） | 目标为情报条目 → 作废并级联重估；目标为命题 → 直接进入重估中 |
| 重复/噪音 | — | — | 审查（去重/初筛） | — |
| 不相关 | — | 需求/采集修正 | — | — |
| 过期 | — | 采集频率、时效参数 | — | — |
| 评级异议 | — | — | — | 触发评级重评（§5.1） |

通用规则：

- 有效/事实错误的奖惩经信用归因（decision-10）落到唯一**责任信源**。
- 命题反馈仅作用于结论态；除事实错误触发重估外，不改信用与配置。
- 反馈默认可信（单人系统前提）；出现多消费方时随 decision-06 一并重启。

## 8. 架构与决策

架构分层见 decision-01（backlog decision）：判断归智能体，记账归确定性系统；智能体写入一律为提案，经校验落账。其余决策见 `backlog/decisions/`。
