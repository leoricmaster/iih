## 1. 是什么

**多智能体情报生产与研判系统**：五类智能体（定向、采集、审查、核实、分析）承担情报循环的全部语义判断；记账层（确定性系统）负责状态机、信用计算、溯源存储、分发检索、调度与反馈路由。消费方声明情报需求、消费产出、给出类型化反馈，反馈驱动系统变聪明。

产出两层知识：

- **情报条目**：偏客观的陈述 + 完整溯源 + 二维评级（信源可靠度 × 内容可信度）；
- **命题结论**：可判真假的陈述，带置信度与推理记录，可引用、可翻案。

核心场景四条：

1. **常驻监控**：情报需求常驻，系统自动盯信源，核实评级后按需分发；
2. **人工录入**：参会/访谈的录音、照片、笔记经对应媒介人工提交，走同一条审查-核实-评级流水线；
3. **研究课题探究**：登记研究课题（问题 + 可选转写答案命题与附件），定向智能体按附件递归分解为子课题与情报需求并催生采集（decision-15），系统持续匹配证据，叶子输入齐时判定出子命题、父课题取子命题合成（构造性测算 v1 由人工）；答案落成命题，可被引用、可翻案；
4. **复核与翻案**：证据变化自动触发评级重评与级联重估，结论始终是当前评估。

## 2. 为什么做

| 痛点 | 现状 |
|---|---|
| 盯不过来 | 信源分散多个媒介，人工盯覆盖不全、易遗漏 |
| 不敢用 | 转载链不透明——"多家报道"可能只有一个独立信源，可信度无从判断 |
| 不沉淀 | 情报与判断散落笔记、聊天记录，假设无人持续求证，自然遗忘 |
| 不可翻案 | 结论依据无处追溯；所引情报事后被推翻，结论静默失效，无任何警报 |

## 3. 重点是什么

核心分界：**判断归智能体，记账归确定性系统**。

1. **判断与记账分离（架构支柱）**：智能体对记账层的写入一律为提案，经校验落账，无溯源不落账（decision-01）；
2. **两层知识，一体闭环（数据支柱）**：情报条目管"世界发生了什么"，研究课题管"想知道什么"（问题线），命题管"信什么、求证什么"（求证线），各有状态机；命题引用情报为证据，研究课题答案落成命题（全景见领域模型 §2）；
3. **反馈三通路（进化支柱）**：类型化反馈路由到信源信用（经信用归因）、需求/采集配置、智能体迭代——使用越多，信源画像越准、配置越贴、智能体越好。

## 4. 特色是什么

- **情报方法论落地**：经典情报循环 + Admiralty 二维评级（A–F × 1–6）+ 事件级合并与独立信源计数 + 转引链穿透——把情报行业数十年的核实纪律做成记账规则；
- **结论是"当前评估"，不是快照**：评级版本化重评、级联重估、推理记录全程留痕——证据变了，评估跟着变，且变得可追溯；
- **信用是算出来的，不是评出来的**：确定性信用公式（版本化、可重放）+ 归因到责任信源，奖惩信号不失真；
- **负知识也是资产**：已证伪的命题默认稳态保留，避免重复提出、辅助排除法。

## 5. 竞品格局

四类相邻产品，各自缺一角：

| 类别 | 代表 | 它们有 | 缺口 |
|---|---|---|---|
| 商业 CI SaaS | Crayon、Klue、Contify | 自动盯竞品、battlecard、AI 摘要 | 面向销售/营销而非情报研判：无核实评级、无研究课题与答案生命周期（判定 / 翻案 / 重估）；不可自部署、数据出域；订阅成本与单人项目错配 |
| 国内商业监测 | 乐思、Meltwater 融文 | 媒体声量、舆情监测、报告 | 舆情/公关范式——无结构化情报 schema、无独立信源计数与转引链穿透、无研究课题与级联重估 |
| 开源 CTI 平台 | MISP、OpenCTI | 方法论同源（可靠性 × 可信度评级、connector 生态） | 域模型为安全指标而非通用情报研判：无判定层（研究课题与答案）、评级重评、级联重估、信用记账；平台重、面向团队，与单人运维冲突 |
| 开源 RSS/AI 阅读器 | Folo、RSSbrew、Miniflux | 自托管采集、AI 摘要、简报 | 阅读器范式——Feed 级非情报级：无 schema 抽取、无事件级合并、无独立信源计数、无评级、反馈不回流 |

采集构件（changedetection.io、RSSHub、Newspaper4k）生态成熟但无整装产品，可作为工具层构件引入；GitHub 同方向早期项目均为个人实验阶段。

**结论**：「定向 → 采集 → 审查 → 核实评级 → 分析研判 → 反馈信用记账」完整闭环在开源界是空位，自建成立。

## 6. 不做什么

- 不做一手实测数据管理（试验数据、测试报告属 PLM/数据平台范畴）；
- 不做舆情情感分析、电商评论分析（属用户研究/营销范畴）；
- 不追求无人参与的自动决策——智能体判定可审计、可翻案，消费方反馈可随时触发重估。

## 7. 关键前提

- 单人开发 + AI 辅助，中长期（工程纪律：LLM 成本由确定性前置过滤控制；自部署组件最少化，引入须论证；流水线按无人值守自动化设计；一切资产代码化/配置化，可迁移）；
- 单消费方（用户本人）：反馈默认可信；多消费方场景出现时另行决策重启；
- v1 范围 = 单消费方的完整情报循环闭环，不含多消费方扩展。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 采而不用，沦为信息坟场 | 分发记录（送达 / 反馈）度量需求覆盖；以开发者本人真实使用验收 |
| 数据合规（robots / 版权 / PII） | 遵守 robots；原文快照仅内部留存用于溯源，分发携带链接而非快照本体 |
